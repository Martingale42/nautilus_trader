## Bugs found

### BUG-1 (Low / Fixed) — Test parametrize IDs show integers, not names

- **Severity**: Low (cosmetic — tests pass but failure output is harder to read)
- **File**: `tests/integration_tests/adapters/sinopac/test_execution.py:2028`
- **Reproduction**: Run `pytest ... -k conditional -v`; observe `[3]`, `[4]`, `[6]`, `[7]`, `[8]`, `[9]` as test IDs.
- **Root cause**: `@pytest.mark.parametrize` used pyo3 `OrderType` enum values without `ids=`. pyo3 enums format as their integer value in `repr()`, so pytest uses the integer as the test ID.
- **Expected**: `[STOP_MARKET]`, `[STOP_LIMIT]`, `[MARKET_IF_TOUCHED]`, etc.
- **Actual**: `[3]`, `[4]`, `[6]`, `[7]`, `[8]`, `[9]`
- **Fix applied**: Added `ids=order_type_to_str` to `@pytest.mark.parametrize`.

### BUG-2 (Low / Pre-existing — not fixed) — TIF warning messages show integer values

- **Severity**: Low (log readability; does not affect order behavior)
- **File**: `nautilus_trader/adapters/sinopac/execution.py:234, 236, 244`
- **Introduced by**: Commit `943fd2f28f` ("Map MARKET_TO_LIMIT to MKP and coerce market TIF") — pre-dates this PR.
- **Reproduction**: A MARKET+DAY order triggers the TIF coercion path; the adapter logs "market orders require IOC/FOK on TWSE; coerced 5 to IOC" (5 is `TimeInForce.DAY` as integer, not "DAY").
- **Expected**: "coerced DAY to IOC"
- **Actual**: "coerced 5 to IOC"
- **Root cause**: `f"...coerced {time_in_force} to IOC"` — pyo3 TimeInForce formats as integer. Fix: use `time_in_force_to_str(time_in_force)` instead.
- **Action**: Not fixed in this QA pass (pre-existing, out of scope). Recommend fixing in a follow-up.
